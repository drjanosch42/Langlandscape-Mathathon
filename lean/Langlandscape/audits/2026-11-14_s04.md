## 4. Required items

**R1. `Hyp.LambdaJL`: the corrected diamond clause is quantified over all `d : ℕ`.**
`Langlandscape/Hyp/LambdaJL.lean:50`: `(∀ d, φ (genGL (.dia d)) * genB (.dia d) = 1)`.
Problem: every other clause is guarded (`ℓ.Prime`, `¬ ℓ ∣ D * M * p`, `ℓ ∣ M * p`, `ℓ ∣ D`); this one is not. It forces
`genB (.dia d)` to be a unit for every natural number `d`, including `d = 0` and every `d` not prime to `M p`. With the
usual junk value `⟨d⟩ = 0` for such `d`, the hypothesis gives `0 = 1` in `TB`, so it is false for the true algebras.
Before the X1 erratum the clause was an equality and junk values were harmless; the erratum made it a unit condition
without adding the guard.
Fix: `∀ d, Nat.Coprime d (M * p) → φ (genGL (.dia d)) * genB (.dia d) = 1`, with one sentence in the docstring. Update
the `HYPOTHESES.md` row text accordingly.

**R2. `evV_UpV_eq_Up` is vacuous for `k ≥ 3`.**
`Langlandscape/Brandt/UpCoeff.lean:176–190`. Hypothesis `hF : ∀ x, evV ℤ_[p] k (F.1 x) = f [x]` with
`f : ZXdual (Utower …) ℤ_[p]`.
Problem: `hF` says that `ev ∘ F` is exactly right `U_s`-invariant over `ℤ_[p]`. For `u ∈ U_s`,
`ev(F(xu)) = ev(ρ(u)⁻¹ F(x)) = F(x)(c, d)` with `(c, d)` the bottom row of `u_p⁻¹`, and these rows run over all of
`p^sℤ_p × (1 + p^sℤ_p)`. So `F(x)(c, d) = F(x)(0, 1)` on a Zariski-dense set, hence `F(x)` is a constant polynomial;
it is homogeneous of degree `k - 2`, so `F(x) = 0` when `k ≥ 3`. Under `hF` the theorem therefore speaks only about
`F = 0` (for `k ≥ 3`). The tex statement (`def:s04-Pk`, proof) is a congruence: `ev(gP) ≡ dⁿ ev(P) (mod c)`, so
`ev ∘ F` descends to `X(U_s)` only modulo `p^s`. The pointwise lemma `evV_UpV` (line 154) is correct and unconditional.
The docstring advertises `evV_UpV_eq_Up` as "`def:s04-Pk`, first half", which it is not.
Fix (one of): (a) restate with values in `ZMod (p ^ s)`: `f : X → ZMod (p ^ s)`,
`hF : ∀ x, (evV … (F.1 x) : ZMod (p ^ s)) = f [x]` (via `PadicInt.toZModPow s`), conclusion for `Up … (ZMod (p ^ s)) f`;
(b) keep the lemma and state in its docstring and in the module docstring that for `k ≥ 3` the hypothesis holds only
for `F = 0`, that the honest content is `evV_UpV`, and that the mod-`p^s` form is not formalized. With (a), add a test
file `LanglandscapeTests/S04/UpCoeff.lean` (none exists now).

**R3. `diamondM`: the identification with the stage-1 diamond is asserted, not formalized.**
`Langlandscape/Brandt/UpAdjoint.lean:147–153` (docstring of `diamondM`: "which lies in `(∏_{ℓ ∣ M} δ_{p,ℓ}) U_s`"),
`:196–198` (docstring of `UpStar_eq_diamondM_UpPrime`), module docstring `:22–26`.
Problem: the plan row S04-L5 asks for `diamondM` "assembled from `diamond`". The file defines it as translation by
`scalarE` instead and proves no comparison with `Brandt.diamond`. The module docstring says so; the two declaration
docstrings state the identification as a fact, and the theorem is cited as "`U_p^* = ⟨p⟩_M U'_p`" with `⟨p⟩_M = ⟨d⟩`.
The sign statement is therefore machine-checked only for the central-idele definition (which is the tex's own
definition in `lem:s04-ekills`); the step "`e_p ∈ δ_d U_s`" is *proved in the tex*, *computed* (H6), not *formalized*.
Fix: add to both declaration docstrings the sentence that the equality with `∏_{ℓ ∣ M} diamond ℓ t_ℓ` is proved in the
tex (`lem:s01-Up`(d), Step 3) and not formalized; record the departure from the L5 row in
`plan/implementation/runs/s04-deviations.md`. Proving the bridge (`diamondM = heckeTHom` of `∏ deltaElt`, from
`scalarE * (∏ δ)⁻¹ ∈ U_s`) is optional (O3).
