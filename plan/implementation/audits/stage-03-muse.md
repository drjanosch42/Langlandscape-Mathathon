### F2 — `deps` field violates schema / not WP ids — major
- **Location:** `stage-03.md:60` `deps = stage-02 partial export (§3)`, `stage-03.md:69` `deps = X1, (S01-M4 soft)`, `stage-03.md:81` `deps = L1 ((i)), L4 ((iii)), S01-L6, S01-L13`, `stage-03.md:77` `deps = S02-L8, X2 (soft: fallback)`, `stage-03.md:86` `deps = L1–L9`, `stage-03.md:71` `deps = M1–M5`, `stage-03.md:113-114` edge list with `C2->M1(soft)` etc.
- **Problem:** `OVERVIEW.md:1` mandates `deps` = WP ids (`S<NN>-<T><k>`), one per dependency, DAG-ordered. Natural-language phrases ("stage-02 partial export", "soft", "((i))", set notation `L1–L9`, ranges `M1–M5`) are not WP ids and cannot be topologically sorted. `X1` depending on an unspecific "partial export" hides its real entry condition (S02-L8, S02-L4b, etc.). Soft/conditional notation conflates hard scheduling constraints with informational links.
- **Suggested fix:** Replace every `deps` cell with explicit WP ids. E.g. `S03-X1: –` (entry needs only `wip-implementation` re-sync, documented in §3), `S03-M1: S03-X1`, `S03-M4: S03-X1`, `S03-L5: S03-L1, S03-L4, S01-L6, S01-L13, S01-L1` (no "(i)" qualifier; split L5 into `S03-L5a`/`S03-L5b` if parallelism is intended — see F6), `S03-L10: S03-L1, S03-L2, …, S03-L9`, `S03-M6: S03-M1, S03-M2, S03-M3, S03-M4, S03-M5`. Remove "(soft)" from DAG; create a separate `soft-info` column or document in §3 as entry conditions, not edges.

### F5 — stated critical path is not the longest path — major
- **Location:** `stage-03.md:146-151` critical-path calculation.
- **Problem:** Chain (A) claimed 485 min (X2→L1→L2→L7→L10→L11) as critical. However `S03-L5` is atomic (single WP, `120 min` agent wall, `stage-03.md:81`) with `deps = L1, L4` (`L4` ← `L3` ← `L1`). Its full chain is `X2(45)+L1(90)+L3(150)+L4(90)+L5(120)+L10(30)+L11(50)=575 min` (+60 min merge gates = 635 min ≈10.6 h), strictly longer than (A)'s 485 min (+60 =545 min ≈9.1 h). The plan's chain (B) artificially splits `L5` into `L5(i)≈80` in W1 and `L5(iii)≈40` in W3, but WPs are not splittable without creating `S03-L5a`/`S03-L5b` (see `OVERVIEW.md:1` sub-WP rule). Even with the split, (B) is `45+90+150+90+40+30+50=495` >485. Throughput estimate "≈9.1 h" is thus understated by ~90 min (1.5 h). Risk 4 delay propagation is also understated: L7 chain is not critical; L5 chain dominates.
- **Suggested fix:** Recompute longest path over atomic WPs: critical path is `X2→L1→L3→L4→L5→L10→L11 =575+60=635 min`. If parallelism inside L5 is desired, split `S03-L5` into `S03-L5a` (arith, 80 min, deps `L1`) and `S03-L5b` (Lean instantiation, 40 min, deps `L4, S01-L6/L13, L5a` or independent) and relabel DAG accordingly. Update wave schedule and §5 merge-point export (L1–L4 early) to reflect new path.

### F10 — soft/fallback edge not a DAG branch — major
- **Location:** `stage-03.md:61` X2 go/no-go, `stage-03.md:77` `X2 (soft: fallback)`, `stage-03.md:113` `X2->L1(soft)`, `stage-03.md:148-151` "If X2 is no-go…".

A soft edge is not a DAG; downstream WPs see different dependencies depending on outcome (X2 pass vs fail). `OVERVIEW.md:1` requires DAG order and immutable deps; stage-03.md's wave plan (W0 L1 starts while X2 builds) assumes both outcomes are transparent, but downstream builds differ (with vs without vendored definitions). Without branching, merge gate cannot recompute.
- **Suggested fix:** Model as explicit branch: `S03-X2` outputs `go/no-go` flag; downstream WPs depend on `S03-X2` hard; L1 has two build alternatives documented (path uses vendored `SubmoduleDiscriminantGroup` else own `Module.Dual` definition). Record decision in `runs/s03.md` and ensure both alternatives expose same names (`Graph.PhiComb`, `Graph.X`) so deps remain valid. Alternatively make X2 hard-blocking L1 (L1 waits for X2 verdict).

### F11 — Lean-technical: missing `Fintype`/`DecidableEq` and universe constraints — minor
- **Location:** `stage-03.md:77` `Graph.WGraph (V E, src tgt, w, 0<w)`, `stage-03.md:78` `Graph.X G := ker ∂`, `stage-03.md:84` weighted adjoints `s_j†` with index weights `[Γ_x:Γ_e]`.
- **Problem:** Definitions omit required `Fintype V`, `Fintype E`, `DecidableEq` instances needed for `Finsupp`/`ker`/`rank` and for Mathlib `CardQuotient` lemmas (`S03-L3`). Without them `LCHK` will fail on missing instances (needs `Fintype` + `DecidableEq` for `AddSubgroup.index_eq_natAbs_det`). Similarly `w: E→ℕ` positivity must be `∀ e, 0 < w e` as a `Prop` field, not just comment, to avoid `Nat` vs `ℕ` coercion issues. `S03-L8` fibre-sum hypothesis `Σ[Γ_x:Γ_e]=q+1` must be stated as `∑ e in filter (s0 e = x) … = q+1` with `Finset` sum, requiring `Fintype`/`DecidableEq`.
- **Suggested fix:** Specify Lean fields: `[Fintype V] [Fintype E] [DecidableEq V] [DecidableEq E]`, `w : E → ℕ`, `hw : ∀ e, 0 < w e`. State `boundary : ℤ[E] → ℤ[V]` as `Finsupp` linear map. Add `Fintype` requirement to L1 acceptance check.
