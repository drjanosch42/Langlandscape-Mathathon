# HJ-7a: tree quotients, Ribet and Ihara natively in C++, weight 2 (Lane C, worker C)

- **Branch:** `impl/hacs-laneC-7`. Code commit e35004ad; the results and this note are in the next commit.
- **Time:** start 05:56Z, milestone 06:16Z.
- **Status words:** every number is *computed* (native C++). Where it equals the stage-02/03 Python value, it is *checked*.

## What

New files are under `code/hacs/src/hacs/Registry/JL/quat/`, built standalone with g++ (build lines in `quat/README.md`). Nothing is linked into `hacs`, and no upstream file was touched apart from one `CHANGES.md` row.

- **`Tree.{h,cpp}`: `hacs_jl::build_tree(ClassSet, q, TreeLevel{N1, N0})` builds BG(U, q) for B_D.** It supports U = O^×, U₀(N0) (N0 prime) and U₁(N1) (N1 a prime power).
  - **Vertices** are X_B(U), the Γ_c-orbits on the level fibres of the maximal-order classes. Level data live in e·I_c/N·I_c, where e is a Hensel-lifted rank-1 idempotent of O/N.
  - **Edges** are X_B(U₀(q)U): the vertex data together with one of the q+1 q-neighbours J ⊂ I_c (`ClassSet::neighbours`).
  - **Stabilisers:** the full stabiliser |Γ_x| (with −1), and w = |Γ_x/±1|.
  - **s₀** forgets J.
  - **s₁** writes J = I_{c'}μ/N_{c'}, with μ found by Fincke–Pohst. The level data move by v ↦ v·conj(μ)/N_c = v·g⁻¹, where g = μ/(qN_{c'}); the diamond q is included.
  - Every edge orbit is checked to have constant s₀ and s₁, as tree.py does with `check=True`.
  - Each edge stores its transport (`EdgeMove`: γ₀, c', μ, γ₁) for weight k.
- **Weight-2 maps (`tree2::`), all exact (`nf::BigInt`):**
  - d = (−s_{0*}, s_{1*}), and the maps s_j^\*, s_{j\*};
  - T_q = H, and H′;
  - αα† for α = d, weighted (⟨x,x⟩ = w_x, ⟨e,e⟩ = w_e) and unweighted, with Ribet's sign variant;
  - the cycle lattice X(G) = ker d (saturated), the weighted Gram, and Φ^comb by Smith form, for BG and for the collapsed two-vertex graph;
  - the Ihara map ι = (s₀^\*, −s₁^\*) : Z[X]² → Z[E], with amalgam.py's MV sign; the transport is trivial at k = 2.
  - The integer linear algebra is a small `zlin` module: a sparse unit-pivot phase, then a dense Smith form, kernel, HNF and Bareiss determinant.
- **`tests/tree_selftest.cpp`:** 702 checks, 0 failing, 0.1 s.
  - The B₁₁ headline.
  - For all 96 cells D ≤ 53, q ≤ 13 at O^×: H = Brandt T_q (`brandt_neighbours`, same class order), row sums, mass, fibre sums, coker d = Z, and rk H₁.
  - Fibre and mass checks at 7 level cells.
- **`tools/jl_tree_dump.cpp`** has one suite per reference file. Each suite uses the generating Python script's case list.
- **`code/python/langlandscape/hacs_bridge/laneC_hj7_compare.py`** runs the binary and compares its output with the reference JSONs; it recomputes nothing.
  - Vertex labellings are matched by a permutation search: colour refinement, then BFS backtracking.
  - It writes `code/results/laneC/hj7_tree_w2.json`, with per-cell `match` flags, diffs, `not_reproduced` reasons and provenance.
  - Binary sha256: f96cf3af…8201.
  - The whole run takes 0.85 s, < 1 GB RSS.

## Deviations

1. **Own `zlin`** (BigInt Smith/kernel/HNF) in `Tree.cpp`. JlCongruence's helpers could not be linked standalone, because they pull in Descent/EnvLever through JlFreeBlockRead. The algorithm is the same, plus a sparse unit-pivot phase, which is needed at E = 3750.
2. **Plan path:** the plan names `code/hacs/src/jl/Tree.{h,cpp}`; the code is in `Registry/JL/quat/`, as the brief says. Not registered in `hacs` or CMake (as HJ-1/2, D6).
3. **"Cuspidal part"** is defined as the degree-zero sublattice of each type. It is stable under weighted αα† by the fibre sums (checked: `stable = true`). It is the integral reading of the plan's "|coker αα†| = 5". It is NEW: the Python reference only has the determinant (q+1)² − λ².
4. **Levels** U₁(N1) are supported for N1 a prime power, and U₀(N0) for N0 prime only. All reference cells are in that range.
5. The comparison is done in Python (GPL, `hacs_bridge/`). All values come from the C++ binary.
