## 1. What was built

`code/hacs/src/hacs/Registry/JL/quat/Level.{h,cpp}`, with conventions (L1)–(L6) in the header:
- **`LevelModel(C, Nbig)`.** A rank-1 idempotent e of O/Nbig: Tree.h `idempotent_mod` on each prime power, combined by
  CRT. For each class, a basis (b1, b2) of e·I_c/Nbig·I_c, with pivot inverses per prime power. It provides `lift`,
  `coords`, `element`, and `move(c, c2, x, div, N)`. `move` is the 2×2 matrix of v ↦ v·x/div between classes: the
  transport used by s1 now, and by every Hecke operator at level in HJ-4b.
- **`LevelSet(model, {N1, N0})`.** X_B(U_1(N1) ∩ U_0(N0)) for composite N1 and N0. It holds the orbits of Γ_c on
  primitive vectors mod N1 and on canonical lines mod N0. It records stab (with −1), w, `locate`, `mass`/`massW` (exact),
  and the unit matrices.
- **`project(from, to)`.** The projection for every inclusion U′ ⊂ U, including U_1(N) ⊂ U_0(N): a U_0 line at a prime
  power dividing N1′ is the line of the U_1 vector.
- **`u0q_correspondence(E, X, q)`.** s0 forgets the q-line. s1 sends the line ⟨y⟩ to J = O·y + q·I_c, then to the class
  of J via μ (Tree.h `find_mu`), with v ↦ v·conj(μ)/N_c. That is the Tree.cpp s1 convention.
- **`fibre_sums_ok`.**
- **`Tower(C, p, smax, M)`.** S_s from one model mod M·p^smax, so π_{s+1,s} is reduction. It also gives the diamonds
  v ↦ d⁻¹v and `delta_free`.

On reuse: Level does not duplicate Tree's code. It generalises Tree's lattice model, because Tree.cpp only handles a
prime-power N1 and a prime N0, while levels.json needs U_1(35) and U_0(4). It calls Tree.h's exported helpers. **Tree.cpp
is untouched.** Tree can switch to `LevelModel`/`LevelSet` later; the point model and the transport are the same.

Self-test: `quat/tests/level_selftest.cpp` (with `--write` → `code/results/laneC/hj3_levels.json`).

## 3. API summary (for HJ-4b and for Tree)

```cpp
LevelModel Mo(C, Nbig);                       // Nbig prime to D; all levels used must divide it
LevelSet X(Mo, LevelSpec{N1, N0});            // X.size(), X.cells()[i].{rep, stab, w, stab_units}, X.first_cell(c)
int X.locate(LevelPoint); LevelPoint X.canon(p), X.act(p, A1, A0);
Mat2 Mo.move(c, c2, x /*O-coords*/, div, N);  // (a, b) -> (a, b) A : v -> v x / div from class c to class c2
std::vector<int> project(Y, X);
Correspondence u0q_correspondence(E /*(N1, N0 q)*/, X /*(N1, N0)*/, q);  // .s0, .s1
Tower T(C, p, smax, M); T.S(s), T.pi(s), T.diamond(s, d), T.delta_free(s);
```

## 4. Deviations (disclosed)

1. **P¹(ℤ/M) indexing.** The plan (§4 HJ-3) asks for HACS's `[C] def:cosetrepsN` (`Hecke/HeckeCosetTables`). Instead, the
   lines are the canonical rep (the lexicographically least unit multiple) of e·I_c/M·I_c, as in levels.py and Tree.cpp.
   Only basis-independent data are compared. Aligning the fibres with HACS's level-N coset tables is open; it matters
   only for a future GL₂-side cell-by-cell comparison.
2. **Implemented, but no Python reference compares it.** levels.json has no U_0(q)U tower maps for S_4; the fibre sums
   and the π/Δ commutation are new checks.
3. **Not linked into `hacs`.** Level.cpp also needs Tree.cpp (for class_units, find_mu and idempotent_mod).
