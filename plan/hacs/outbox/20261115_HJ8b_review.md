## Findings

- **m1 (minor, latent soundness gap)** `jl_defect.py:1355`. In `gl2_block_unramified`, a p-adic factor whose
  reduction is not a single simple irreducible is skipped with `continue`. That covers ramified places, and also
  places where the generic A is not p-monogenic. The code does not test whether such a factor meets m. So "exactly one
  place … carries the residual polynomials" (docstring, l.1325, and the WP note's Method) is checked only among those
  places. A skipped place that meets m would make S_m strictly larger than O_v, and η = (1) could then be wrong. H3 is
  unaffected (PARI: all places unramified, no old systems). Fix: when a skipped factor's residual minimal polynomials
  match m_id (or cannot be read), return `open`.
- **m2 (minor, tautological checks)** `jl_defect.py:1409`. For étale blocks, `rank_definite_eq_rank_new_gl2` and
  `thm_E_identity` are literal `True`, and `ranks` is set to `blk["rank"]` (l.1363 ff.), i.e. copied from the definite
  side. The real rank comparison is the gate `place_degree == blk["rank"]` (l.1363), and a mismatch becomes `open`,
  never "disagree". `etaB_eq_eta_new` and `identity_with_etaB` are the same test (eB == 0). So for the 7 étale blocks,
  "agree" means: the GL₂ side admits the argument (rank by degree) and v_p η^B = 0. The note should say this, and a
  rank mismatch should be reported as a disagreement.
- **m3 (minor, matching for f > 1)** `jl_defect.py:1359`. The places are matched to m_id by one minimal polynomial per
  ℓ. When two or more generators have residues of degree f, those per-ℓ minimal polynomials do not determine one
  maximal ideal: (α, β) and (α, β^p) give the same per-ℓ minimal polynomials. The "exactly one match" rule makes this
  fail-safe (two matches give `open`), and H3 has a one-to-one pairing, so nothing changes. It is still worth one line
  under D3.
- **m4 (minor, wording)** `20261115T1055Z_HJ-8b.md:46`. "0 open" is next to 11 census rows whose status is `open`
  (not run). `summary.blocks_open = 0` counts only the cells that were run. Suggested wording: "0 open among the 44
  run blocks; 11 cells not run (open)".
- **m5 (minor, provenance)** `20261115T1055Z_HJ-8b.md:51`. The 16 rows without a sign record are claimed to have "a
  unique HACS sign". The file does not show this: those rows have no `assignments_total`. It does show
  `sign_robust = true`, so the numbers do not depend on the sign. Either say that, or cite the run-1/run-2 logs.
  Also, the 12 run-1-only rows were computed at 1647d0b5, before the oracle code. That is harmless for robust rows,
  but D8 could say it.
- **m6 (minor, tests)** `test_hacs_bridge_jl_defect.py`: there is no test of `gl2_block_unramified`, which is the
  route behind 7/9 H3 blocks. Add one toy test, or an H3 cell with k = 4 (cheap, k ≤ 8).
