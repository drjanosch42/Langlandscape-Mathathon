The agentic process of team Langlandscape

Team Langlandscape (Abhijit A J, Fabian Januszewski) works on the Jacquet–Langlands correspondence at Caltech × SAIR Mathathon 2026: mathematics (LaTeX), a Lean 4 formalization (Lean v4.35.0, frozen Mathlib), computations (Python/PARI, HACS) and a talk. This folder documents how the work is done: by a hierarchy of Claude Code agents across four machines, coordinated through git. It is written for later documentation and for presenting the process itself (slides, write-up).

Summary (state: 2026-11-14, ~18:10 PST)

A single global master session on Fabian’s node runs the project autonomously from 2026-11-14 01:20 PST. It delegates every task to subagents (Opus coordinators; Sonnet/Haiku/Opus workers; Fable auditors). Two helper sessions on other machines (TITAN, CONCEPTD) run all Lean builds, and Abhijit’s node (a separate Claude account) takes work packages and cross-account reviews over a git message channel. The work went through a staged mathematical plan (6 stages, audited by Muse Spark Open and then by Fable), detailed implementation plans (audited the same way), and then stage-by-stage execution. In stage execution, work packages (WPs) are stacked on unverified drafts, checked in batched integration rounds on the remote Lean nodes, and closed by an early full gate, parallel Fable Lean and chapter audits, and a from-scratch final gate on TITAN with a cross-check on CONCEPTD. 3. The per-stage loop

  1. Kickoff (X1): sync wip-implementation from main, stubs, aggregator files, drivers, strand briefs.
  2. WPs in parallel (≤ 8 agents per delegating agent), each in its own worktree on impl/sNN-<wp>. Lean WPs stack on unverified drafts of their upstream WPs instead of waiting (F14).
  3. Batched integration rounds: the stage master merges several drafts into impl/sNN-int<k>, adds a .titan/ spec commit, and writes an outbox file. The global master relays it to TITAN or CONCEPTD (warmest build, free slot). Results come back as inbox files with verbatim errors and goal states. Fixed drafts go into the next lettered round (int1 → int1a → int1b …). One round per cycle amortises the remote round trip of a few minutes.
  4. Merge gate: a WP is merged into wip-implementation only after its spec line passed on the merged tree, and only with or after its upstream WPs (stacking rule O6).
  5. Early gate (sNN-gate1) as soon as the core Lean WPs are green: all targets, Audit/PrintAxioms.lean (every declaration’s axioms ⊆ {propext, Classical.choice, Quot.sound}), forbidden-token grep, check_frozen.sh.
  6. Parallel Fable audits on the early-gate commit: Lean audit (agents/roles/lean_audit.md) ∥ chapter audit (agents/roles/mathematics_chapter_audit.md). Required remarks become audit-fix WPs in the same stage (F17).
  7. Final gate from scratch (sNN-final-1, unseeded build) after the audit fixes; cross-check on the second node.
  8. Closure (agents/roles/milestone_closure.md): outbox file …_milestone-closure-sNN.md (delivered / verification / open issues / request) and runs/sNN.md (per-WP times, rounds, deviations).
  9. Merge and mirror (global master): push wip-implementation, git merge --no-ff into main (checks: no literature/, no .lake, no file > 10 MB, frozen paths unchanged), push, fast-forward wip-implementation, remove worktrees, then rclone copy the milestone PDFs to Drive (copy only) and launch the next stage master.

Experiment strands (model study) run inside this loop on 1–2 WPs per stage; see model-study.md. Remote WPs for Abhijit’s node are sent as batches of packages; Lean drafts from there are accepted only by a build on TITAN or CONCEPTD (master_resume.md §3).

4. Frozen-toolchain guards

The Lean toolchain (v4.35.0) and Mathlib (rev 56a00585…) are frozen on every node (agents/rules/frozen.md). - Forbidden for all agents: lake update, lake clean, lake exe cache get, manifest/toolchain edits, writes into the frozen Mathlib or its dependency farm. Dependencies are symlinks into the frozen copy. - Wrappers only (tools/lbuild.sh, lfile.sh, check_frozen.sh, link_deps.sh, titan_batch.sh): they take locks, cap memory and check the frozen trees. Nobody calls lake directly. - Pin guard: every wrapper checks tools/pins.sha256 (sha256 of lakefile.toml, lake-manifest.json, lean-toolchain) and the absence of .lake/package-overrides.json before any lake call, and exits 99 on failure; exit 99 means stop and alert the global master (agents/rules/lean.md). Reason: a missing manifest would make Lake run a full update through the frozen farm symlinks. - check_frozen.sh: verifies that the frozen trees are untouched; part of every gate. It caught the bad import of 2026-11-14 12:23 PST (see lessons.md). - Worktree seeding only by cp -a --reflink=auto (never hard links); removal only by git worktree remove (never rm -rf). - Single exception: Abhijit’s node may run a direct lean draft check of Mathlib-only files, outputs outside the repo, followed by a find <frozen tree> -newer <marker> check (frozen.md).

Model-vs-task study

Goal: for each task class (track × difficulty), find the cheapest model that does not lengthen the stage’s wall time. Protocol: plan/implementation/EXPERIMENT_PROTOCOL.md (PROT). Data: …-wt/impl/plan/implementation/experiments/{LOG.md, SUMMARY.md,events.tsv}. Resulting policy: agents/rules/model-selection.md.

1. Design

  • Strands. For a selected WP, two (stage 1: up to three) models implement the same brief at the same minute, from the same base sha, each in its own worktree on exp/sNN-<wp>-<model> (PROT §2.1). Everything a build node or auditor sees is neutral (a/b job ids, titan-in/* refs, no model names); model names appear only in LOG.md.
  • Blind audits. Each strand gets its own fresh auditor (order randomised), fed only the diff without commit metadata, the brief, the stage-tex excerpt and an independently run acceptance check. The auditor lists defects (critical/major/minor) and scores a rubric Q = correctness 0–4 + completeness 0–2 + interface fidelity 0–2 + maintainability 0–2 (PROT §2.3).
  • Pass = acceptance green, 0 critical, 0 major, ≤ 3 minor. Weighted findings W = 3·crit + 2·maj + min. A failing strand gets a same-model fix if W ≤ 5 and improving, otherwise escalates one rung (haiku/muse/mistral → sonnet → opus → fail); at most 3 fix rounds (PROT §2.4). Stage 3 (E8) override: exactly one planned opus fix round for the opus reference, none for the fable challenger.
  • Scoring (PROT §3): active = implementation + audit + fix minutes (decision metric; build waits excluded); wall reported beside it; cost_idx = Σ weight × agent minutes with weights muse 1, haiku 2, mistral 3, sonnet 4, opus 10, fable 20; classes A < 40, B < 150, C ≥ 150.
  • Decision rule (PROT §4): speed first: the passing strand with the smallest active wins unless another passing strand is within τ = max(15 % of best active, 5 min) and quality-equivalent (|ΔQf| ≤ 1, equal correctness); then lower cost_idx wins. Tie rule: higher Q0, then the cheaper model, then the reference strand. Exactly one passing strand wins; none → all-fail. A reference strand may be merged at mechanical acceptance (merged-first) so downstream work is not blocked.
  • Budget: at most 1–2 strands per stage after stage 1, only for undecided or confounded cells (OVERVIEW §5.2).
